# Contributing

Public Purpose Lab is in its founding phase. Review, questions, scenario
challenge, and evidence are welcome. Substantive external code contributions
are not yet being accepted because the licence and contributor model have not
been agreed.

## Useful contributions now

- identify an unclear claim, hidden assumption, or missing risk;
- challenge a scenario using public or synthetic examples;
- suggest an authoritative public interface standard or evidence source;
- propose a bounded experiment and the evidence that would decide it; or
- improve documentation without introducing confidential or encumbered content.

Open an issue before investing significant effort. Do not submit personal data,
client material, employer-confidential information, credentials, security
secrets, proprietary interface specifications, or content covered by an NDA.

## Working style

- Start with the public-purpose problem and expected outcome.
- Distinguish proposals, demonstrations, measured results, and production claims.
- Record meaningful trade-offs in an architecture decision record.
- Keep components independently understandable and their decision authority
  explicit.
- Add tests and evidence in proportion to the risk of the change.
- Use plain language and avoid claims of endorsement or readiness that the
  evidence does not support.

## Technology proposals

Technology choices must be justified by the scenario and operational model.
Rust is the intended backend language, but other mechanisms—including cREXX
assets—should be proposed only where their particular value and trust boundary
are clear. cREXX is neither prohibited nor mandatory.

## Conduct and security

Participation is governed by the [Code of Conduct](CODE_OF_CONDUCT.md). Report
security concerns using [SECURITY.md](SECURITY.md), not a public issue.
