# Initial demonstrators

Demonstrators give the shared platform a concrete reason to exist. Each one must
show a meaningful organisational problem, the decisions made, the resulting
events and actions, and the evidence needed to judge the outcome.

The detailed, screen-level implementation gate is the founder-approved
[demonstration scenarios and functional requirements](demonstration-scenarios-and-functional-requirements.md).
It defines the common runtime demonstrations, deployed component baseline,
visible acceptance evidence and mandatory gate show-and-tell reports. Gate A is
closed; Gate B is implemented and awaiting visual closure evidence and founder
acceptance.

- [Charity systems discovery and reporting](charity-systems-discovery-and-reporting.md)
- [Care disruption and rebooking](care-disruption-and-rebooking.md)

Both use synthetic people, organisations, records, and operational data. All
external interfaces are simulated until separate authority, governance, and a
specific integration purpose exist.
