# Public documents

This repository is the canonical home for Public Purpose Lab's public
programme, policy, governance, demonstrator and architecture documents.

The private `site-publicpurposelab-org` repository owns website presentation
and deployment. Website pages may summarise or adapt this material for
visitors, but they do not become a second source of programme or policy truth.

## Document set

| Area | Purpose | Location |
|---|---|---|
| Programme | Defines what the Lab is establishing, the outcomes sought, the initial and future horizons, and how progress is evidenced. | [`programme/`](programme/README.md) |
| Policy and governance | Defines authority, participation, conduct, security and other standing rules governing the Lab and its work. | [`policy/`](policy/README.md) and the linked root documents |
| Architecture | Defines system responsibilities, boundaries and lasting technical decisions. | [`architecture/`](architecture/README.md) |
| Demonstrators | Defines the synthetic business scenarios used to test the programme and architecture. | [`scenarios/`](scenarios/README.md) |
| Brand | Provides approved project identity assets and usage guidance. | [`brand/`](brand/README.md) |

## Authority and publication

- Maintained Markdown is the authoritative document form.
- PDF files are distribution copies and should identify the source and review
  date from which they were produced.
- A website adaptation should link to or identify its canonical source and
  retain the same maturity, authority and claim boundaries.
- Local changes, draft PDFs and website previews are not published policy or
  programme commitments until they pass the project's approval and release
  process.
- Detailed implementation truth remains with the relevant implementation
  repository; programme documents describe direction and demonstrated use.

Each substantial document should state its status, review date, owner or
decision authority where relevant, scope, and relationship to supporting
evidence.
